# 改密 Worker

把账号管理器「待改密」里的账号，用浏览器自动把 Steam 密码改掉，然后回传，
账号自动回到「可用」。

```
账号管理器                          本 Worker
─────────                          ─────────
待改密 ──┐                          ┌── 拉任务
         │   /api/automation/*      │
         ├─────────────────────────▶├── 认领 + 取账号密码
         │                          │
         │                          ├── 🌐 打开 Steam，自动登录
         │                          ├── ⏸  验证码 → 你手动完成（脚本自动检测后接管）
         │                          ├── 🔑 填入新密码并提交
         │                          ├── 🔐 回传新密码
待改密 ◀─┼─────────────────────────┤
可用   ◀─┘                          └── 完成
```

---

## 一、安装

```bash
cd worker
npm install
```

只装 `playwright-core`（几 MB），**它不下载浏览器** —— 直接用你系统里的 Chrome 或 Edge。

## 二、配置

1. 打开账号管理器 →「**待改密**」界面顶部的卡片，或「**设置**」页 → 复制 **API Key**
2. 把 `.env.example` 复制成 `.env`，把 Key 填进 `VAULT_API_KEY`

```bash
copy .env.example .env
```

必填的只有两项：`VAULT_BASE`（默认就对）和 `VAULT_API_KEY`。
其余都可以先不动。

## 三、跑起来

**先记住一件事：worker 是账号管理器的「客户端」。**

```
账号管理器（必须先开）           worker（后开）
  双击 启动.bat          ──▶     node index.mjs
  浏览器里解锁
```

**顺序不能反。** 服务没开、或者保险库锁着，worker 都会失败。

### 先体检一下

```bash
node doctor.mjs
```

一条命令依次检查：配置对不对 → 服务在不在 → 保险库锁没锁 → API Key 有没有效 →
有几个待办任务。**出问题先跑这个**，它会直接告诉你卡在哪一步、怎么修。

### 自测（改代码或怀疑出问题时）

```bash
npm test
```

跑两套：

| 测试 | 内容 | 需要浏览器 |
| --- | --- | --- |
| `test-password.mjs` | 5000 个样本验证密码规则：长度、字符集、字母开头、三类齐全、分布均匀 | 否 |
| `test-flow.mjs` | 用**模拟 Steam 页面**复现「输入太快 → 密码无效」，并验证当前节奏能成功 | 是（Chrome/Edge） |

`test-flow.mjs` 特别值得留着：它把当初那次真实失败的原因固化成了可重复的测试。
如果有人把 `TYPE_DELAY_MS` 调成 0，它会立刻红。

### 然后再跑

**强烈建议按这个顺序，不要一上来就跑全自动：**

```bash
# ① 先验证接口链路 —— 不开浏览器、不改任何密码
node index.mjs --once --dry

# ② 再只走到登录，把浏览器留给你看
node index.mjs --once --stop-after-login

# ③ 完整跑一个（建议先在 .env 里把 PAUSE_BEFORE_SUBMIT 改成 true）
node index.mjs --once

# ④ 没问题了，常驻轮询
node index.mjs
```

| 命令 | 作用 |
| --- | --- |
| `node index.mjs` | 常驻，每 `POLL_SECONDS` 秒查一次任务 |
| `node index.mjs --once` | 处理完当前待办就退出（适合调试） |
| `node index.mjs --dry` | **只验证接口**，不开浏览器、不改任何密码 |
| `node index.mjs --stop-after-login` | 只走到登录页，浏览器留给你 |

`Ctrl+C` 停止（会等当前任务跑完；再按一次强制退出）。

**用别的配置文件跑**（比如测试环境）：

```bash
node index.mjs --once --config=../../.env.test
```

`--config` 可以指向任意 `.env` 文件，路径相对 `worker/` 目录解析。不指定就用 `worker/.env`。

> 为什么叫 `--config` 而不是 `--env-file`？因为 `--env-file` 是 **Node 自己的内置参数**，
> 会被 Node 直接消费掉，根本传不到脚本里（实测踩过这个坑）。

## 四、流程中会发生什么

**① 自动的部分**

- 打开 Steam 改密向导
- 自动填写账号密码并登录，同时**取消勾选「记住我」**（不留长期会话在这台机器上）
- 填入新密码：**10~12 位随机，字母开头，只含数字与大小写字母**（三类各至少出现一次）

**关于新密码，你会看到什么**

每次处理一个账号，控制台都会把这次生成的新密码打出来：

```
▶ gykqp72395  (渔力全开)
  任务 _O-2gAlXRroidBDw · 触发原因：使用时间已用完（1 分钟）

  🔑  本次新密码：  AdlqZ3YxEdxC   (12 位，字母开头)
      ↑ 请留意这一行；改密成功后它会写进账号库，失败时它就是你的兜底

  浏览器已启动：channel=chrome，有界面
  ...
  ✓ 检测到成功：页面提示「密码已更改」
  ✓ 已自动同步 账号回到「可用」  (18 秒)
    新密码 AdlqZ3YxEdxC 已生效，并写入账号库
```

跑完一轮还会在结尾列一遍汇总。不想让密码留在终端回滚缓冲区里，
就在 `.env` 里设 `SHOW_PASSWORD=false`。

**② 验证码：能自动就自动，不能就转人工**

账号在管理器里**关联了邮箱**时，登录遇到 Steam Guard 会**自动去邮箱取码填上**：

```
  检测到验证码输入框 —— 去邮箱取码…
  取到验证码：K4F7B
```

取码由服务端完成（它自己在邮箱里轮询，间隔 10s → 14s → 18s… 递增，不打太密）。

**取不到时会转人工**，不会卡死：

```
  ⚠ 邮箱里没找到验证码（等了 90 秒邮件还没到）
  ┌────────────────────────────────────────────────────────────┐
  │ 请在浏览器窗口里手动输入 Steam Guard 验证码               │
  │ （脚本会自动检测，你填完它继续）                           │
  └────────────────────────────────────────────────────────────┘
```

**只尝试一次，不会反复轰炸邮箱。** 相关配置：

| 参数 | 默认 | 说明 |
| --- | --- | --- |
| `AUTO_CODE` | `true` | 填 `false` 一律手动 |
| `CODE_WAIT_SEC` | `90` | 让服务端在邮箱里最多轮询多少秒 |
| `LOGIN_TIMEOUT_MS` | `180000` | 登录阶段最多等多久（要留够人工输码的时间） |

**没关联邮箱的账号**会直接走手动流程，行为和以前一样。

登录后如果还要手动导航到改密页，脚本同样会等：

```
  ┌────────────────────────────────────────────────────────────┐
  │ 接下来需要你手动操作                                        │
  │    1. Steam Guard / 邮箱验证码（若上面没自动取到）           │
  │    2. 进入「修改密码」页面（能看到两个密码输入框就够了）      │
  │  脚本会自动检测，最多等 8 分钟，检测到就接管继续。           │
  └────────────────────────────────────────────────────────────┘
```

**你不需要按任何键。** 在浏览器里做完，脚本发现「新密码表单」出现就会自动接手。
等待时间用 `ASSIST_MINUTES` 调。

**③ 又回到自动**

填新密码 → 提交 → 校验结果 → 回传 → 账号回到「可用」。

**③ 全程自动，不需要你确认**

改完之后**没有任何"请人工确认"的环节**。worker 会自己判断改密是否成功，
成功就直接调接口把账号放回「可用」，并打印确认：

```
  ✓ 检测到成功：页面提示「密码已更改」
  ✓ 已自动同步 账号回到「可用」  (18 秒)
    新密码 AdlqZ3YxEdxC 已生效，并写入账号库
```

判定成功用的是**四路信号，任一路命中即可**（会告诉你是哪一路）：

| 信号 | 说明 |
| --- | --- |
| ① 页面文案 | 出现「密码已更改 / successfully changed」之类 |
| ② URL 变化 | 离开了改密向导页 |
| ③ 表单消失 | 两个密码框没了，说明表单被结果页替换 |
| ④ 会话失效 | 被跳到登录页 —— Steam 改密后会让会话失效，这也是成功 |

只有抓到**明确的错误文案**才判失败。为什么是反过来的？因为漏判成功会让工具里
存着旧密码、账号等于丢了；而漏判失败最多是白跑一次，下次重试即可。

**④ 出错不会卡住**

失败时浏览器会多留一会儿方便你看现场，但这**不阻塞失败上报**：

```
  ⚠ 浏览器会保持打开 60 秒方便你看现场（不影响失败上报，到点自动关）
  ✗ 失败：...  ← 立刻上报，立刻能重试
```

（旧版本这里会死等 5 分钟才上报，已经修掉。）

**⑤ 中途被杀掉也能自愈**

worker 跑到一半被 `Ctrl+C` 或电脑重启，任务会一直停在「处理中」，
而轮询只拉「待处理」—— 那个账号就永远卡在「待改密」。

现在 worker 启动时会自动把超过 `STALE_TASK_MINUTES`（默认 20 分钟）的
「处理中」任务**放回队列重试**，不需要你手工干预。

## 五、新密码恢复文件（重要，请务必了解）

**为什么需要它：**

想象这个场景 —— Steam 上密码**已经改成功了**，但回传到账号管理器时网络断了。
如果新密码只存在于内存里，进程一退，**你就永远不知道新密码是什么，那个账号等于锁死**。

所以：**在把新密码提交给 Steam 之前**，worker 会先把它写进
`out/recovery-<任务ID>.json`。

| 情况 | 恢复文件 |
| --- | --- |
| 回传成功 | **自动删除** |
| 提交给 Steam 之前就失败了 | 自动删除（密码没改，文件没意义） |
| 提交之后失败 / 回传失败 | **保留**，并在终端把新密码打出来提醒你 |

看到保留的恢复文件时，请去 Steam 确认一次密码到底改没改成功，然后手动删掉它。

> 这个文件是**明文**的。它是"账号可能锁死"和"本地多一个明文文件"之间的取舍，
> 我选了前者。回传成功就会删，正常情况不会长期存在。

## 六、哪些是验证过的，哪些不是

我不想让你以为这东西"开箱即用、包成功"。诚实说明：

| 部分 | 状态 |
| --- | --- |
| 接口链路（拉任务/认领/上下文/回传/失败重试） | ✅ **端到端实测通过** |
| 浏览器启动（驱动系统 Chrome） | ✅ **实测通过** |
| 打开 Steam 改密向导 | ✅ **实测通过** |
| 登录页选择器（填账号密码、点登录、取消记住我） | ✅ **对 Steam 真实页面实测通过** |
| 登录失败识别（给出 Steam 的原始报错） | ✅ **实测通过**（"请核对您的密码和帐户名称并重试。"） |
| 登录**之后**的步骤（验证码、进入改密表单、提交） | ⚠️ **无法预先测定** —— 需要真实账号和真实验证码。已做成"自动尝试 + 交还给你 + 自动接管"，但第一次真跑时请盯着看 |
| 改密成功与否的判定 | ⚠️ 文案无法预先确定，见下面的设计说明 |

### 关于"成功判定"的一个刻意设计

默认策略是：**没捕获到明确错误，就认为成功并回传新密码。**

反过来（没看到成功文案就报失败）后果更糟：密码其实已经改了，但工具里存的还是旧密码 ——
账号等于丢了。所以只有抓到明确的错误文案才判失败。

## 七、卡住了怎么办

**worker 会自己告诉你哪里卡住。** 任何一步失败，它会 dump 当前页面的真实结构：

```
  ✗ 步骤失败：登录 Steam
  ── 页面结构（照着这个就能补选择器）──
    URL: https://help.steampowered.com/zh-cn/login?...
    可见输入框 (2):
      <input type=text> label=「用帐户名称登录」
      <input type=password> label=「密码」
    可见按钮 (1): 「登录」
    可见文本: ... 请核对您的密码和帐户名称并重试。 ...
  ── 截图：out/screenshots/xxx.png
```

拿着这个输出，去 `steam.mjs` 里改对应那一步的选择器就行。

**或者用检查工具自己看：**

```bash
# 看改密向导首页
node inspect.mjs

# 带界面打开，登录之后每按一次回车 dump 一次，方便看后续页面
node inspect.mjs --headed
```

`--headed` 模式下你可以手动登录进去，然后不断回车，一步步看清登录之后的页面结构。

## 八、安全与风控

- **一次只处理一个账号。** 默认每个之间等 `INTERVAL_SECONDS`（45 秒）。
  **别调太小** —— Steam 对短时间大量改密很敏感，可能触发风控甚至临时锁定账号。
- **默认不留长期登录态。** 每次都会取消勾选「记住我」。
- **`.env` 和 `out/` 已在 `.gitignore` 里**，别把 API Key 提交出去。
- **API Key 权限不小** —— 它能读到全部账号的当前密码。别泄露。
- **只用于你自己的账号。** 这是给你管理自己的多账号用的。

## 九、常见问题

> 出问题**先跑 `node doctor.mjs`**，它会把下面这几类问题一次查清楚。

**Steam 报「输入的密码无效」**
这是**输入太快**导致的，不是密码格式问题。

Steam 的改密页是 React 应用。如果两个密码框用一次性填充（`fill()`）塞完值就立刻点「更改密码」，
React 的内部状态还没更新完、表单校验还没跑，提交上去的其实是空值 —— Steam 就判无效。

worker 已经改成**逐字符输入**（模拟真人打字），并且在每个框之后、点击提交之前都留出等待时间：

| 参数 | 默认 | 作用 |
| --- | --- | --- |
| `TYPE_DELAY_MS` | 45 | 逐字符输入时每个字符之间的毫秒数 |
| `FIELD_SETTLE_MS` | 400 | 每个密码框填完后等多久（给表单校验留时间） |
| `SUBMIT_SETTLE_MS` | 1200 | 点提交前等多久（给 React 状态更新留时间） |

**这几个值不要轻易调小。** 如果还是报「输入的密码无效」，把它们都调大试试
（比如 `TYPE_DELAY_MS=80`、`SUBMIT_SETTLE_MS=2500`）。

`TYPE_DELAY_MS=0` 会退回一次性填充，那是已知会失败的旧行为。

**`连不上账号管理器（http://127.0.0.1:8787）`**
服务没开。worker 是客户端，必须先把账号管理器跑起来：
双击项目根目录的「启动.bat」，等它打印出界面地址，再跑 worker。
（注意是**项目根目录**的启动.bat，不是 worker 目录。）

**`API Key 被拒绝`**
两种可能：
1. `.env` 里的 `VAULT_API_KEY` 还是 `.env.example` 的占位符，没换成真的
2. 你在设置页重置过 API Key，旧的自然失效

去「待改密」页顶部卡片或「设置」页复制最新的一次，**整段替换** `.env` 里 `VAULT_API_KEY=` 后面的内容。

> 顺带一提：**不要改 `config.mjs` 里的代码**。那行 `process.env.VAULT_API_KEY` 里的
> `VAULT_API_KEY` 是**变量名**，不是值。把 Key 直接写进代码会语法错误
> （Key 里有 `-`，而 JS 变量名不允许），而且 Key 会混进代码里。

**`账号管理器当前处于锁定状态`**
界面用主密码解锁即可，worker 会自动恢复。

**`没有可用浏览器`**
装 Chrome 或 Edge，或者在 `.env` 里改 `BROWSER_CHANNEL=msedge`。

**登录一直失败**
看终端给出的 Steam 原始报错。如果是「请核对您的密码和帐户名称并重试」，
说明工具里存的密码和 Steam 上的不一致（可能之前手动改过没同步）。

**卡在验证码那一步**
默认等 8 分钟。嫌短就调大 `ASSIST_MINUTES`。

**想让脚本自己读邮箱验证码**
目前没做。这是"访问权限"问题不是"页面理解"问题 —— 需要 IMAP 登录你的邮箱抓验证码。
想加的话告诉我。

**想换成 LLM 自动处理验证码之后的步骤**
`steam.mjs` 里 `reachNewPasswordForm()` 那个函数就是"交还给你"的地方，
把它换成 `stagehand.act(...)` 之类的调用即可，其余部分不用动。
